# 사랑흐름 문지기 규칙

**현재 버전 · v1 · 260810**

> 이 문서를 고치실 때는 맨 위 주석의 버전과 이 줄을 함께 올리십시오.
> 문서와 코드의 버전이 어긋나면 문서가 소설이 됩니다 — 260804에 실제로 그 일이 났습니다.

| 짝이 되는 파일 | 이 문서가 기준으로 삼는 버전 |
|---|---|
| `lf/pass.js` | v1-1 (260810) |
| `lf/enter.js` | v8 (260810) |


여권번호가 어디서 오고 어디로 가는지, 문이 언제 열리는지를 정한 한 장입니다.
**이 문서와 `/lf/pass.js` 두 개만 보면 됩니다.**

---

## 1. 원칙

### 번호는 이 순서로 찾습니다
1. 주소의 `?id=`
2. 그 창의 기억 (`sessionStorage`)
3. 기기의 기억 (`localStorage`)

찾으면 **세 곳 모두에 다시 심습니다.** 다음 화면이 또 묻지 않게.

### 문은 이렇게 엽니다
| 상품 | 판정 |
|---|---|
| 마음 여행지도 | 번호가 있으면 엽니다. 바깥 조회가 막혀도 손님을 세우지 않습니다 |
| 마음 여행편지 | 위와 같습니다 |
| 한 편의 기록 | 대장을 확인하고 엽니다. 이 판정은 자서전 화면이 그대로 합니다 |

### 어느 문으로 들어와도 첫 문은 이렇게 정합니다
| 손님이 어디까지 왔는가 | 그 자리에 서는 첫 문 |
|---|---|
| 번호가 어디에도 없다 | 여권을 넣는 칸 |
| 하다 만 것이 있다 | 이어 하기 |
| 마친 것이 있다 | 다시 펼쳐 보기 |
| 여권은 있는데 아직 안 떠났다 | 여행 시작하기 |

바깥 조회가 늦거나 막히면 **기다리지 않고 「이어 하기」를 먼저 세웁니다.**
답이 오면 그때 정확한 문으로 바꿉니다.

---

## 2. 화면에 붙이는 법

모든 화면 — `<head>` 안, 되도록 맨 위:

```html
<script src="/lf/pass.js"></script>
```

잠긴 화면(지도 · 지도 결과 · 편지)은 바로 다음 줄에 한 줄 더:

```html
<script>LFPass.guard();</script>
```

**이 두 줄이 전부입니다.** 잠금 코드를 화면에 다시 쓰지 마십시오.

---

## 3. 부품을 고칠 때

문 그리는 부품(`/lf/enter.js`)을 고치면 **`/lf/pass.js` 안의 `PART_V` 한 글자만** 올립니다.
화면 파일은 건드리지 않습니다.

> 260804에 부품을 v5·v6으로 두 번 올리면서 화면 열두 곳의 꼬리표를 빠뜨려,
> 헤더에는 "v6으로 올렸다"고 적혀 있는데 실제로는 넉 달 동안 옛 부품이 돌았습니다.
> 그 일이 다시 나지 않게 하려고 꼬리표를 화면에서 걷어 문지기 안으로 옮겼습니다.

---

## 4. 문지기 밖에 남는 것

이건 문지기가 **못** 합니다. 제자리에서 고쳐야 합니다.

- 여권을 처음 만드는 일(발권 `issue()`)
- 결제 · 주문대장 · 입금 확인
- 자서전 여행권 검문 (바깥이 판정)
- 화면 안 내용 — 질문 · 결과 그리기
- 바깥 잠금 (서버가 최종 방어)
- 새 화면을 만들 때 문지기를 부르는 한 줄 — 사람이 넣어야 합니다

## 5. 260810 작업 기록

### 왜 했나
게이트가 여권을 낼 때 번호를 **그 창의 기억에만** 넣고 기기에는 안 넣었습니다.
지도·편지·자서전 화면은 둘 다 넣는데, 번호가 처음 나오는 자리만 반쪽이었습니다.
그리고 잠금 셋은 기기의 기억을 **읽지 않았습니다.**
그래서 여권을 받은 손님이 창을 닫으면 다음 날 처음 온 사람이 되어 게이트로 튕기고
결제번호를 다시 대야 했습니다.

### 손댄 곳

| 파일 | 버전 | 손댄 곳 |
|---|---|---|
| `lf/pass.js` | **신설 v1** | 문지기 — 번호 찾기·심기·문 판정·링크에 번호 붙이기·부품 부르기 |
| `journey/index.html` | v8-17 → **v8-18** | 잠금 19줄 → 문지기 2줄 |
| `journey/result.html` | v1-11 → **v1-12** | 잠금 19줄 → 문지기 2줄 |
| `letter/index.html` | v260804-2 → **v260810-1** | 잠금 19줄 → 문지기 2줄 |
| `gate.html` | v28 → **v29** | head 문지기 한 줄 · 발권 콜백에 `LFPass.seal` 한 줄 · `goJourney` 기기 기억 · `lfGoPassport_` 기기 폴백 |

### 곁들이로 함께 풀린 것
화면 열여섯 곳의 ☰ 메뉴가 「여행지도 보기 · 편지 · 여권으로 입장」을
**번호 없이 빈손으로** 보내고 있었습니다(문 쉰 개).
문지기가 누를 때 번호를 붙이므로 **화면 마크업은 한 글자도 안 건드립니다.**

### 안 건드린 것
발권 `issue()` · GAS 주소 넷 · 결제 · 재여행 차단 · 자서전 여행권 검문 ·
`ITEMS` 가격블록 · 드로어 마크업 · `.ways` · 갈림선 · 자리표 · GA4 · 색값 · 화면 본문

### 2순위 — 부품을 실제로 갈아끼움 (260810)

화면 열두 곳이 `\`/lf/enter.js?v=4\`` 를 직접 부르고 있었습니다.
그 줄을 걷고 `\`pass.js\`` 한 줄로 바꿉니다. 앞으로 부품 판 번호는 `\`PART_V\`` 한 글자입니다.

| 파일 | 버전 |
|---|---|
| `lf/enter.js` | v6 → **v8** |
| `index` `enter` `find/index` `l/index` `letter/index` | 각 한 단계 |
| `journey/index` `journey/result` | 각 한 단계 |
| `memoir/index` `ask` `ritual` `book` | 각 한 단계 |
| `gate` | v29 → v30 |

부품이 바뀜 것:
- 번호 모양만 맞으면 **바깥에 묻기 전에 먼저 문을 엽니다**(`basic()`). 조회는 뒤에서 돌고, 답이 오면 정확한 문으로 바꿉니다
- 조회가 막혀도 문은 열려 있습니다
- 번호를 **기기의 기억에서도** 찾습니다
- 화면에 들어오자마자 아는 번호가 있으면 첫 문을 먼저 세웁니다

견본 여권번호도 걷었습니다 — `enter.html`의 LF-W8Z2Q, `l/index.html`의 LF-K7M3P.

### 3순위 — 겹쳐 도는 것 걷기와 게이트 아랫줄 (260810)

**옛 알약** — `lfPaintResume()` 이 공용 부품과 같은 일을 두 벌로 하고 있었습니다.
260804에 다섯 화면만 끄고 세 곳(게이트·지도·편지)을 빠뜨렸습니다.
**함수와 CSS 는 남기고 부르는 줄만** 끄었습니다.

**게이트 아랫줄** — 「번호를 넣으세요」 바로 밑에 「번호를 찾으세요」가 큰 버튼으로 붙어 있었습니다.
이제 이 순서입니다.

```
— 이미 사랑흐름 여권이 있으시면 —
[ 여권칸 LF-XXXXX ]
[ 내 여행지도 이어가기 → ]        ← 번호를 넣는 순간 섬니다
번호가 기억나지 않으시면 · 여권 찾기 →   ← 작은 줄
— 아직 사랑흐름 여권이 없으시면 —
[ 사랑흐름 여행 둘러보기 ]
[ 여행 고르러 가기 ]
```

새 CSS 0줄 · 새 색 0개. 기존 `gsplit` · `ways` 그대로 썼습니다.

> ⚠ **다음 사람을 위한 경고 — 부품의 숨김 규칙**
> 부품은 화면에 `\`/find/\`` 링크가 이미 있으면 자기 줄을 감추는데,
> ☰ 드로어에도 같은 글자가 있어 **어느 화면에서도 「여권 찾기」가 안 보였습니다.**
> 드로어는 화면 밖으로 밀려만 있어서 「숨음」 판정에 안 잡힙니다.
> 거기에 자리표(inslot) CSS 가 표제 두 줄과 찾기 줄을 한 묶음으로 `\`display:none\`` 했습니다.
> **원인이 둘이었고 둘 다 고쳤습니다.**

### 4순위 — 남은 화면과 자서전 (260810)

**부품을 못 받았던 세 화면** — `pay` · `showcase` · `apply`.
260804 공용 입구 부품 때 빠졌고, 그래서 옛 알약만 돌고 있었습니다.
문지기 한 줄을 붙이고 옛 알약 호출을 끓습니다.

| 파일 | 버전 |
|---|---|
| `pay.html` | v14-34 → **v14-35** |
| `showcase.html` | v5-21 → **v5-22** |
| `apply.html` | v23 → **v24** |

**자서전 — 진짜 구멍이 여기 있었습니다.**
의식(`ritual`)과 입구(`index`)는 번호를 진작 세 곳(주소·창·기기)에서 찾고 있었는데,
**정작 오래 머무르시는 질문 화면과 책 화면이 주소만 보고 있었습니다.**
자서전은 쓰시는 기간이 일 년입니다. 창을 닫았다 다시 오시면 무조건 잠금 안내가 떴습니다.

| 파일 | 버전 | 고친 것 |
|---|---|---|
| `memoir/ask.html` | v42 → **v43** | `passport_()` 가 주소·창·기기 순서로 찾게 |
| `memoir/book.html` | v28 → **v29** | 주소의 `id` 칸만 똑같이 세 곳을 보게 |

> ★ **검문 자체는 한 글자도 안 건드렸습니다.**
> `gateThenBoot_` · MEMOIR 게이트 · `mlock` · 조회 실패시 통과 규칙 모두 그대로.
> 바뀐 것은 **번호를 찾는 순서** 하나뿐입니다.
> 여권이 아예 없으신 분은 여전히 잠금 안내가 뙙니다(자서전은 fail-close 확정 원칙).

## 6. 이제 모든 화면이 같은 순서를 씁니다

260810 작업으로 **여권번호를 찾는 순서가 사이트 전체에서 하나로 통일됐습니다.**
주소 → 그 창의 기억 → 기기의 기억.

두 가지 방식이 공존합니다. 서로 어긋나지 않습니다.

| 방식 | 쓰는 곳 |
|---|---|
| 문지기 `LFPass.no()` | 문지기를 부르는 화면 전부 |
| 화면 자체 `lfPassport()` | 예전부터 있던 함수. 같은 순서를 씁니다 |

## 7. 문지기 밖에 남는 것

이건 문지기가 **못** 합니다. 제자리에서 고쳐야 합니다.

- 여권을 처음 만드는 일(발권 `issue()`)
- 결제 · 주문대장 · 입금 확인
- 자서전 여행권 검문 (바깥이 판정 · fail-close 확정 원칙)
- 화면 안 내용 — 질문 · 결과 그리기
- 바깥 잠금 (서버가 최종 방어)
- **새 화면을 만들 때 문지기를 부르는 한 줄** — 사람이 넣어야 합니다

여권이 필요 없는 화면(`showroom` · `partner` · `trust` · `about` 등)은 그대로 둡니다.
그 화면들은 `lfPassport()` 를 이미 가지고 있거나, 여권과 무관한 자리입니다.
